# Planet Lab — P-001 第一阶段

> 本段描述 P-001 到 P-002 的历史交接。当前进度与环境见 [PROJECT_STATE.md](../PROJECT_STATE.md)，试玩见 [P-002.2 说明](../P0022.md)。下文保留 P-001 地图及参数的历史说明；固定镜头、空中跟随重力转向等旧描述不再代表当前行为。原始双星球地图 `Scenes/Lab.tscn` 仍可 F6 运行，使用更新后的控制器。

Godot 4.6.1 .NET / C# / .NET 8。当前只实现静止球形和胶囊形双星球；花生与贯通通道尚未实现。

## 启动和操作

1. 用 Godot **.NET 版本**导入本目录 `project.godot`。
2. 点击编辑器的 Build（构建），然后 F6 运行 `Scenes/Lab.tscn`，或直接 F5 运行主场景。
3. 初始角色在左侧球形星球顶部。A/D 沿局部表面移动；Space 沿实际支撑法线跳跃。
4. 接地时在游戏画面中按住鼠标左键，反方向拖拽；白色箭头指向发射方向，松手发射。无需点中小角色。
5. 瞄准期间角色的位置和速度冻结。拖拽少于 6 像素视为取消，不发射；Esc 取消瞄准。空中不可发射。
6. R 重新载入场景。镜头固定以观察两颗星球，飞出画面后也可按 R 返回。

建议首轮旅行：用 D 从球顶走到球的右侧，停下；向左略向下拖约 163×25 像素，发射速度约为 (650, -100)。在胶囊左端落地后，可向右略向下拖拽返回。拖拽像素以游戏逻辑画布为准；窗口缩放可能影响实际鼠标移动距离。第一轮不用追求最大力度。

调试信息：重力来源、重力向量/大小、速度、接地、实际支撑星球与法线、发射方向与速度。红线表示重力方向，绿线表示支撑法线，白线表示发射；淡蓝外圈表示影响区域边界。调试界面目前使用英文。

## 可调参数

打开 `Scenes/Lab.tscn`，选中节点，在 Inspector 中调整：

| 节点 | 参数 | 默认值/含义 |
|---|---|---|
| Player | GroundAcceleration / GroundDeceleration | 650 / 800，地面加减速 |
| Player | MaxGroundSpeed / JumpSpeed | 200 / 290，速度单位为世界像素/秒 |
| Player | AirAcceleration / AirControlSpeed | 65 / 200，少量空中控制；不会截断已有发射速度 |
| Player | MaxLaunchSpeed / LaunchSpeedPerPixel | 1100 / 4，最大初速度与拖拽倍率 |
| Player | MinimumDragPixels | 6，误触死区 |
| Player | SupportProbeDistance | 0.2，支撑检测距离，不修改位置、不强制贴地 |
| Sphere / Capsule | GravityStrength | 550，恒定加速度大小 |
| Sphere / Capsule | InfluenceRange | 500，从吸引边界向外扩展的距离，不是圆心半径 |
| Sphere / Capsule | AttractionGeometry | 可配置 CircleShape2D / CapsuleShape2D |
| CollisionShape2D 子节点 | Shape | 实体形状，默认与对应吸引资源共享 |

改变共享资源尺寸会同时改变实体和吸引几何。要分离两者，请先将其中一个资源设为独立资源。星球仅支持平移、旋转，不支持缩放节点；请修改 Shape 的 Radius/Height。实体 CollisionShape2D 保持相对父节点零位移、零旋转。玩家当前使用半径 12 的圆形碰撞体，外观箭头转向不改变碰撞形状。

胶囊 Height 包含两端半圆。当前半径 130，总长 560；节点旋转 90° 后横放。

## 技术边界

- `SurfaceGeometry` 查询吸引轮廓，`Planet` 管理实体/吸引参数，`GravitySelector` 决定来源，`Player` 统一控制角色，`Lab` 管理界面。
- 吸引方向指向最近边界点；恰在边界上时向实体内部施力。位于吸引体内部时向最近边界施力，等距中心使用固定局部 +X 方向。这是当前技术约定，尚不是复杂轮廓的正式玩法规则。
- 来源选择为**最近有效吸引边界**，精确等距时由场景顺序决定。没有隐藏滞回、重力混合或方向平滑。影响范围外无重力；切换只改变加速度，不直接改位置和速度。
- 地面输入加减切向速度，落地保留碰撞响应后的速度，再由地面减速处理。空中速度保持世界坐标，局部方向变化不会旋转已有速度。
- `FloorSnapLength=0`，不永久贴地。0.2 像素支撑探测只观察实际实体接触，且拒绝分离速度；高速仍能离地。
- 发射明确覆盖原速度，符合测试规则；这是与重力切换不同的行为。
- 后续复杂轮廓应提供整体外边界查询，不能遍历凸分解内部接缝作为吸引面。

## 编译和自动化回归

在项目目录运行：

```powershell
dotnet build NewGame.csproj
./Tests/Run-Tests.ps1
# 也可用自己的 Godot 路径，物理频率仍为项目设定的 120 Hz：
./Tests/Run-Tests.ps1 -Godot '你的Godot目录/Godot_console.exe' -RenderFps 60
```

测试启动实际 Godot 场景和碰撞引擎，不使用第三方测试框架。输出位于 `.godot/test-results/physics-*.log`。失败返回非零退出码。

覆盖：几何距离与法线、影响范围、静止稳定、两个方向绕行、球形和胶囊各 8 个位置跳跃/着陆、空中惯性、发射限制/上限/暂停、双向旅行、着陆后移动、无中途重置的连续往返、高速切向离地。绕行与飞行期间逐帧检查穿透和非有限速度。

默认物理频率 120 Hz。测试中的距离/时间阈值针对默认地图和参数；修改玩法参数后，测试可能合理失败，不能简单删除断言。

## 已知限制与人工验收

- 最近归属规则在等距位置附近仍有反复切换的理论风险；当前往返测试各切换一次，不代表任意布局都不会抖动。
- 胶囊当前测试最多出现 2 个物理帧的接地丢失，间隙小于 0.1 像素。临界帧跳跃/瞄准可能被拒绝；本阶段没有擅自添加土狼时间或跳跃缓冲。
- 高速、极小半径、低物理频率以及任意分离吸引配置未穷举验证。
- 需要亲自确认鼠标拖拽舒适度、移动/跳跃手感、局部左右方向理解、落地体验和旅行难度。自动化通过不能替代这些验收。
- 当前编译在受限网络下出现 NuGet `NU1900` 漏洞元数据查询警告；并非编译错误。没有关闭安全审计来隐藏警告。
